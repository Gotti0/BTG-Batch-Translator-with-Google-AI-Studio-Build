## 배경

AI Studio에서 갈라진 포크(Remix-BTG---Batch-Translator-for-Gemini)는 공통 Git 이력 없이 원본보다 약 4.8배 커져 있었다.
사용자가 고른 기능은 RPM 디스패처와 429 상세 파싱, 스냅샷 시스템, 표지 생성과 텍스트 EPUB 생성, 완료 알림음·무음 루프, PDF 입력이다.
설정 저장 방식은 포크처럼 브라우저 저장소에 남기지 않는 쪽을 골랐다.

## 문제

포크 코드는 최종 검수·용어집 워크플로·에디터 초안 등 이식하지 않는 기능과 얽혀 있어 파일째 복사할 수 없었다.
포크 설계를 그대로 옮기면 생기는 결함도 있었다.

- 스냅샷 Web Worker 경로는 오래된 자동 스냅샷을 지울 때 원본 refCount를 줄이지 않는다. 그래서 시작할 때마다 전수 보정이 필요했다.
- 포크는 IndexedDB 'BTG_Database'를 v4로 올린다. 같은 출처에서 원본(v1)과 번갈아 쓰면 원본 쪽이 VersionError로 열리지 않는다.
- 원본의 콘텐츠 안전 패턴에 '500'이 있다. 429 본문의 'limit: 1500'이 여기에 걸려 Rate Limit이 분할 재시도로 잘못 분류될 수 있었다.

비교 단계에서 포크에 "PiP 진행 모니터"가 있다고 보고했으나, 실제로는 설정 필드만 남은 미사용 기능이었다. 사용자에게 정정했고 이식 대상에서 뺐다.

## 결정과 근거

- RPM: 포크의 pumpQueue 디스패처(모든 번역 루프를 작업 큐로 재구성) 대신 우선순위 게이트(RequestGate)를 두었다.
  - 모든 번역 API 호출이 게이트에서 허가를 받고, 슬롯이 열리는 순간 서브청크를 메인 청크보다 먼저 내보낸다.
  - 포크가 고치려던 핵심 결함은 "워커가 미래 슬롯을 선점해 서브청크가 새치기하지 못함"이다. 이것은 게이트로 해결된다.
  - 원본의 여섯 개 번역 루프를 다시 쓰지 않아도 된다. 대신 포크와 달리 한 청크의 서브청크는 같은 워커에서 순차 처리된다.
- 429: 진행 중인 요청까지 취소하던 기존 동작을 "새 요청만 멈추고 이미 보낸 요청은 마무리"로 바꿨다.
  - 이미 보낸 요청은 할당량을 이미 썼고, 원본의 취소는 Promise.race일 뿐이라 HTTP 요청도 끊지 않았다.
  - 이를 위해 stopRequested(새 작업 금지)와 abortRequested(결과 폐기, 사용자 중단 전용)를 분리했다.
  - 같은 이유로 분할 재시도가 중단되면 '[중단됨]'이 섞인 번역문을 성공으로 반환하던 경로를 실패로 바꿨다.
- 스냅샷 저장소:
  - 새 DB 'BTG_SnapshotDB'를 쓴다.
  - 메타와 본문 스토어를 나눠 목록 조회가 큰 본문을 읽지 않게 했다.
  - 원본 정리는 refCount 대신 메타 전체를 훑어 참조 없는 원본을 지우는 방식으로 했다. 카운터 드리프트가 구조적으로 생기지 않는다.
  - Web Worker는 버렸다. postMessage와 IndexedDB put 모두 메인 스레드에서 구조화 복제를 하므로 이득이 작고, 포크에서는 정리 누락의 원인이었다.
- 자동 저장: 3초 디바운스와 10초 최대 대기를 쓴다. 원본의 EPUB 번역은 isRunning을 켜지 않으므로 "실행 중이면 스로틀" 방식으로는 EPUB 진행 중 저장이 계속 밀린다.
- 이전 데이터: localStorage 설정·용어집과 이전 자동 저장을 수동 스냅샷 하나로 옮긴 뒤에만 키를 지운다. 포크는 모듈 로드 시점에 키를 지워 설정을 잃는다.
- ZIP: 포크와 같은 구조로 쓰고 읽어 두 앱 간 이동이 가능하게 했다. 포크의 시스템 지침·퓨샷 설정은 원본의 프리필 필드로 되돌려 읽는다.
- 포크 EPUB 생성기는 표지가 없어도 매니페스트에 표지 항목을 넣는다. 원본에서는 표지가 있을 때만 넣는다. 다만 내보내기 검증은 포크처럼 표지·제목·작가를 요구한다.

## 검증

- vitest 52개 통과. 이 중 이번 작업에서 추가한 테스트는 RequestGate 우선순위·간격·취소, 실제 Gemini 429 본문(QuotaFailure·RetryInfo) 파싱과 '1500' 오분류 회귀, 429 마무리 중단, PDF 입력 페이로드, 스냅샷 저장·복원·원본 공유·정리, 자동 스냅샷 세션·개수 한도, ZIP 왕복, 포크 형식 ZIP과 이전 JSON 변환, 레거시 이전이다.
- 기존 EPUB 테스트 4개는 vitest 환경이 지정되지 않아 DOMParser가 없어 실패하고 있었다. jsdom 환경을 지정하면서 통과한다.
- tsc --noEmit과 vite build가 통과했다.
- 브라우저(개발 서버)에서 텍스트 업로드 → 3초 내 자동 스냅샷 생성 → 새로고침 → 복원 안내 → 복원(파일·프로젝트 제목)까지 확인했다. 복원 직후 중복 자동 스냅샷이 생기지 않는 것도 확인했다.

## 미해결

- 로컬에 API 키가 없어 실제 Gemini 호출은 검증하지 못했다. 대상은 번역, 429, 표지 생성, PDF 입력(PDF 글자를 모델이 정확히 읽는지 포함)이다.
- 포크 ZIP 가져오기는 단일 파일 프로젝트만 테스트했다. 포크는 여러 파일을 '\n'으로, 원본은 '\n\n'으로 이어 붙이므로, 여러 파일 프로젝트는 청크 오프셋이 어긋날 수 있다.
- EPUB 모드 스냅샷 복원과 대용량(수십 MB) 원문의 자동 저장 비용은 측정하지 않았다.
- npm install이 package.json에 선언되지 않은 채 설치돼 있던 jsdom과 @types/react를 지웠다. 둘 다 devDependencies로 명시해 복구했다. package-lock.json이 새로 생겼다.
